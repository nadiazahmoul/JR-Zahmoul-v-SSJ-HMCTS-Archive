# 00_CHRONOLOGICAL_RECORD

## Purpose
This folder is a single, chronological record of all JR-related correspondence and administrative artefacts (incoming and outgoing), organised by date.

The organising principle is deliberately simple:

**Time is the only taxonomy.**

This structure is designed to:
- minimise cognitive load,
- preserve an auditable sequence of events,
- support rapid chronology-building for court and public-interest review.

## How to use this folder
### Canonical structure (preferred)
Each calendar day has a canonical folder in the format:

`YYYY-MM-DD/`

Each date folder contains (or points to) everything that occurred on that day, regardless of document type (email, letter, notice, draft, instruction summary, etc.).

### Legacy folders (retained to avoid breaking links)
Earlier materials may appear in legacy folders such as:
- `YYYY-MM-DD_Court_Correspondence_Received/`
- `YYYY-MM-DD_Court_Correspondence_Received_Second/`

These legacy folders are retained to preserve existing GitHub links and references.

Where legacy folders exist, the canonical `YYYY-MM-DD/` folder for that date contains a short pointer (README) directing the reader to the legacy location(s).

## Naming convention (files)
Where possible, files are named in the format:

`YYYY-MM-DD_[short descriptor].[ext]`

Examples:
- `2026-01-23_Expert_Instruction_Summary_Initial_Enquiry_v1.0_FINAL.docx`
- `2026-01-18_ACO_Email_JR_Case_Progression.eml`

## What this folder is / is not
- **This is:** a navigational and evidential record ordered by date.
- **This is not:** a thematic library (no subject-based subfolders).

## Note on versioning
Documents intended for reuse (e.g. instruction summaries) are versioned in the filename. When updated, a new version number is created rather than overwriting prior versions.
